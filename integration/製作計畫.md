# 三包整合製作計畫

授權：使用者於 2026-10-31 要求開始製作，自主取捨、不再逐項詢問，可用 subagent，預計約八小時。沿用禁止啟動遊戲、全部工作放在 Database、避免完整三包備份的約束。

## 完成條件

- 一個具有完整資源視圖的獨立 MO2 整合環境，以及可識別的預設整合配置。研究用部分鏡像不充當成品。
- 全部原模組均有目錄、來源與採用／重複／替代／停用理由；互斥框架自主擇一，不把「整合」解讀成所有互斥插件同時啟用。
- 啟用插件有明確唯一來源、主檔閉合、有效先後順序、可容納的 full/light 索引與適用的執行檔／SKSE DLL。
- 可追加內容通過記錄、資源及框架檢查；驗證過的修復納入適當版本。未解來源問題另列且不假報已修復。
- 動畫、身形、材質、LOD 及 Synthesis 的產物逐一判定重建或重用；重用須記錄其適用範圍及實際來源。
- 以實際 MO2 虛擬環境與 xEdit 完整載入核對，保存診斷、處置及已知限制。由於禁止啟動遊戲，交付不宣稱已做遊戲內測試。
- 原三包內容不覆寫，所有新檔、日誌、快取、工具設定及可回退的差異位於 Database；有方便的開啟入口與後續修改注意事項。

## 階段與驗證關卡

1. **規劃**：比較基底及框架、同名異版與異名同源、unique 內容和插件索引預算；產生整體採用清單。
2. **架構驗證**：使用任務內小型 fixture 驗證硬連結與修改前斷開；盤點完整 game root、模組、overwrite 及生成工具，確認空間和寫入路徑。
3. **建立**：先建立完整基底資源視圖與獨立設定，再逐批增加可驗證內容。所有可寫檔案獨立；共用大資源只供讀取，生成工具使用獨立輸出。
4. **內容驗證**：檢查主檔、插件版本、二進位結構、資源與腳本依賴及主要覆蓋；逐批決定採用或隔離，保存理由與前後雜湊。
5. **生成與修補**：按照最終採用內容重建受影響的輸出，或證明原輸出仍適用。先量測與預算，避免空間耗盡。
6. **總驗證**：實際完整 MO2 VFS 探針、xEdit 完整載入與目標／全記錄診斷、來源不變性及空間檢查，修正可重現的製作缺陷。
7. **交付**：更新機器可讀清單、研究資料庫、入口及操作說明；明確標記完成項、未啟用候選和未測 runtime 範圍。

## 檔案與並行責任

- `integration/`：中央計畫、清單、製作工具、檢查點及證據；子代理僅寫自己的 `research/<task>/`。
- 正式環境預定 `Database/UnifiedSkyrim/`；基底確定後建立。
- `baseline/` 既有研究證據優先只讀；新的整合決策與檔案清單使用獨立整合資料庫。
- 主代理負責正式檔案建立、共用設定、GUI、執行與最終驗證；子代理先做唯讀研究及自有小型試驗，避免同時改寫。

空間初測約 113 GiB free，暫定保留 32 GiB。這是工作門檻，尚非對全部生成輸出的足夠空間證明。沒有完整備份不影響保留原來源與小型回退；硬連結本身不提供寫入隔離。
